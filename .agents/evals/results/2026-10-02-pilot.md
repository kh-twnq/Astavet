# First real Codex harness pilot (2026-10-02)

Four paired repair trials ran on isolated copies. Application commit: `14d80d339e9d526887250478aef61f5b8dea338b`; nested `.agent/` commit: `ffa6fa48b46834eeb762ce537a9146f2cf69bcf2`. All used Codex CLI 0.159.3, `gpt-6-sol`, `workspace-write`, `approval_policy=never`, one agent per run, and the same seed and task prompt within each pair. The candidate also received the current `AGENTS.md`, `.agent/README.md`, `.agent/harness/`, and architecture test. The baseline is the two repositories' pinned HEAD, **not** an exact snapshot of every dirty file present immediately before phase 1.

## Independent outcome review

- **Java:** The untouched seed made `ProductVariantTest` fail (`reservesAvailableStock`, 1/3 failure). Both agents restored the production stock subtraction. Independent `./gradlew test --tests 'com.astavet.entity.product.ProductVariantTest' --rerun-tasks` passed 3/3 on each final checkout. The candidate added a relevant negative quantity assertion.
- **COD:** The untouched seed made the existing `OrderServiceTest` fail (`rejectsReusingAnIdempotencyKeyForDifferentCustomerData`, 1/2 failure). Both agents restored lookup by the same normalized key used by the advisory lock, without changing stock reservation or conflict logic. Each added a relevant retry regression test. Independent focused Gradle tests passed 3/3 on both final checkouts, with all `ASTAVET_TEST_DATABASE_*` variables unset. PostgreSQL integration tests were skipped because no disposable database was established.
- **Checkout:** Both agents restored the `customerName` JSON key expected by backend `CreateOrderRequest`; Vietnamese UI and client call remained. `npm test` passed 3/3, lint exited 0 with four existing image warnings, and `tsc --noEmit` passed. Candidate's tests, lint, and typecheck were rerun with Node 22 because its agent had used the default Node 16. Both agent builds failed while fetching Google Fonts; independent default builds failed in both checkouts when Turbopack could not bind a local port. Consequently the required build was **not verified**, so both records mark `outcome_pass=false` despite the source-level contract repair. No HTTP checkout flow was exercised. Existing frontend tests do not detect the seeded JSON key mismatch.
- **README:** Both agents restored `cd backend` followed by `./gradlew test`, checked it against the Gradle project, and kept the separate PostgreSQL test database warning. `git diff --check` passed. Application tests were appropriately not run for this documentation-only correction.

Review of final statuses and `git diff --check` found no unrelated source edits. The frontend `tsc` produced an untracked `tsconfig.tsbuildinfo` artifact in both isolated checkouts. Candidate overlays were compared against the prepared candidate state, not mistaken for agent edits. The stock, COD, and checkout production files returned to their pinned HEAD contents after the seeded defect was fixed.

## Measurement limits and next gate

Gradle could not start inside Codex's sandbox: the user cache lock was denied, and moving the cache to `/private/tmp` still hit local socket or download restrictions. Reviewer Gradle tests ran **after** wall time measurement. The checkout build could not be verified even outside the agent sandbox in this environment. These failures measure environment handling as well as task execution.

The Java pair used the original trial prompt suffix and had no clone-local GitNexus index; both agents queried the live `Astavet` index after clone path lookup failed. For the other three pairs, both clones were indexed with GitNexus 1.6.12 under distinct aliases and the shared prompt suffix directed agents to their checkout paths and limited sandbox troubleshooting. Thus cross-case aggregate medians combine two trial setups; only within-case comparisons share a setup. GitNexus `detect-changes` can miss untracked guidance and tests, so graph output was not used as a sole cleanliness verdict. User-level Codex memory/configuration was available to both variants. The first Java baseline CLI launch blocked before the agent started and was excluded from the pair.

The first pair's suffix was `Work alone; do not delegate. Do not commit, push, deploy or publish.` The later suffix added: `If Gradle or npm is blocked by sandbox permissions, try at most one safe workaround, then report the blocked check; an independent reviewer will run it. For GitNexus, use this checkout's absolute path as the repo and do not use the live Astavet index.` Each pair's complete prompt SHA-256 is recorded in the JSON and checked for equality.

The baseline Java run used an earlier `run.py` that omitted usage from `run.json`; its input/output token counts were recovered from the `turn.completed` event in its raw JSONL stream. The later runner writes usage and the complete prompt hash directly.

Repeat the cases on fresh checkouts with a test environment where default Gradle and Next builds can run, a fixed Node 22 PATH, clone-local graph indexes, and isolated or consistently disabled user memory. Run multiple pairs per case before changing harness policy on performance grounds.
