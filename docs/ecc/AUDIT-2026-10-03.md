  assets đã cài độc lập với source checkout.

  nhận 328 skills ECC và ba generic roles; không nhận 16 repo skills AstaVet.

  không chứa domain instructions AstaVet.

  `[mcp_servers.ecc-chrome-devtools] enabled = false` vào project vì gây lỗi;

  đạt 86,81% line coverage; không suy rộng sang installer Python hoặc ứng dụng.
- Source baseline mở rộng từ 90 lên 93 file để pin thêm ba TypeScript rules.

RED đã quan sát trước implementation cho adapter/installer/audit còn thiếu;
thêm RED cho symlink manifests, empty build manifests, language-specific rules
và duplicate project launcher. GREEN xác nhận sau sửa bằng cùng regression suite.

Chưa đo model reliability/cost/latency hoặc chạy subagents, native hook execution,
browser actions và product gates. Những phần đó là evidence riêng; không dùng
unit tests hoặc native registration thay thế. Application coverage/E2E/CI gaps
trong baseline dưới đây vẫn là phạm vi riêng của AstaVet.

## Phạm vi đích đã được làm rõ: dùng cho mọi project

Người dùng xác nhận AstaVet là nơi xây dựng cấu hình; mục tiêu là một Codex
harness dùng cho mọi project. Vì vậy kết luận phía dưới về AstaVet chỉ là kết quả
kiểm tra một project tích hợp, không phải kết luận hoàn thiện harness toàn cục.

Kiểm tra user-level hiện tại: `~/.codex/config.toml` bật `ecc@ecc`; chưa có
`~/.codex/AGENTS.md`, `~/.codex/AGENTS.override.md`, `~/.codex/agents/` hoặc
`~/.agents/skills/`. Không thay đổi user-level state trong audit.

| Thành phần hiện tại | Phạm vi | Khoảng trống đối với mục tiêu mọi project |
| --- | --- | --- |
| Native ECC plugin | User-level, enabled | Catalog chung đã có; chưa kiểm tra discovery/runtime ở project thứ hai |
| Native hook | Plugin declaration, trusted trong observation AstaVet | Chưa kiểm tra execution/context restore ngoài AstaVet |
| Workflow trong AGENTS.md | AstaVet | Chưa có user-level workflow chung được triển khai |
| 16 repo skills và Markdown rules | Repo AstaVet | Project khác không kế thừa các file này chỉ vì nằm trên cùng máy |
| 5 roles và config | Project `.codex/` | Chưa có bộ role chung ở user config; Java roles là specialization |
| Routing | File patterns và asset paths AstaVet | Chưa detect stack hoặc resolve assets/checks của project khác |

**Kết luận theo mục tiêu thực:** nguồn/catalog ECC toàn cục đã được cài, nhưng
workflow, routing, roles và verification được tùy biến mới triển khai ở phạm vi
AstaVet. Chưa hoàn thiện một harness portable cho mọi project. Vị trí lưu source
không quyết định phạm vi áp dụng; đường dẫn discovery và config layer mới quyết
định phần nào được Codex nhận trong từng project.

Kiến trúc đích nên có ba lớp:

1. **Core chung:** workflow, cách chọn skill/rule, boundaries, review/report và
   role trung lập stack, triển khai ở phạm vi user; giữ model/settings cá nhân.
2. **Adapter theo stack:** nhận diện Java/Gradle, Next/npm và stack khác; resolve
   guidance/checks từ project thực tế, có fallback cho stack chưa biết. Chỉ nạp
   adapter liên quan, tránh mang invariants AstaVet sang project khác.
3. **Project overlay:** AGENTS, API/domain invariants, commands và memory của
   từng project; AstaVet là một overlay và một fixture kiểm thử.

Ưu tiên cho mục tiêu này: tách core khỏi overlay → đóng gói install/update có
phạm vi rõ → audit nhận target directory → kiểm thử ít nhất project Java,
frontend và project không có overlay. Đánh giá discovery, routing, command
selection, instruction precedence và tránh rò context giữa project. Thêm
coverage/E2E/CI của AstaVet là quality work cho một adapter/project, không tự
hoàn thiện harness dùng chung.

Không cần mỗi project đều cài tất cả MCP, chạy mọi skill hoặc dùng cùng test
runner. “Dùng cho mọi project” cần core và fallback portable, cùng adapters có
phạm vi hỗ trợ được kiểm chứng; chưa thể khẳng định hỗ trợ mọi stack.

## Phát hiện và ưu tiên

### P1 — Frontend chưa được CI kiểm tra

`.github/workflows/verify.yml` chỉ có job backend: ECC checks, Java build/tests,
PostgreSQL integration và test reports. Không có `npm ci`, frontend test/lint/build.
`scripts/verify.sh frontend` có entrypoint local nhưng workflow không gọi nó.
Một PR frontend vì vậy có thể qua workflow này mà không chạy frontend checks.

Đề xuất: thêm job frontend độc lập với Node 22, `npm ci` theo lockfile rồi chạy
wrapper frontend. Kiểm tra GitHub run thực tế và branch protection riêng; audit
này chỉ xác nhận cấu hình đã commit, không xác nhận CI remote đã xanh.

### P1 — Mục tiêu coverage 80% chưa được đo hoặc enforce

`backend/build.gradle` không có JaCoCo/report/coverage verification;
`frontend/package.json` không có script coverage hoặc dependency coverage
provider khai báo trực tiếp. Các hướng dẫn 80% trong skills/rules và AGENTS không
phải bằng chứng đạt 80%. Build hiện cũng không có Checkstyle/PMD/SpotBugs.

Đề xuất: đo coverage service/domain trước, tập trung giá/tổng, stock reservation,
idempotency, cancellation và payment transitions; bổ sung báo cáo CI và threshold
có phạm vi phù hợp. Không dùng coverage toàn repo để thay thế kiểm tra hành vi.

### P1 — Chưa có E2E cho các luồng quan trọng

Inventory test hiện có: một frontend test file cho cart model; backend unit/domain,
boundary và PostgreSQL integration tests. Không thấy Playwright/Cypress config,
E2E runner hoặc E2E test suite trong repo. MCP Chrome DevTools không thay thế
test đăng nhập, CSRF, checkout, duplicate submit và quản trị qua browser.

Đề xuất: tạo smoke E2E với dữ liệu/database cô lập cho checkout COD và admin;
thêm ca lỗi/auth quan trọng, rồi chạy trong CI. Đây là thiếu hụt test so với yêu
cầu unit/integration/E2E của ECC, không phải kết luận sản phẩm có lỗi cụ thể.

### P1 — Security workflow hiện chủ yếu là hướng dẫn

Workflow và wrapper không gọi dependency/CVE scanner, secret scanner hoặc
automated security analysis. Không có `.github/dependabot.yml` hay SECURITY.md
trong inventory GitHub hiện tại. Sandbox/on-request và security rules đã có;
chúng không chứng minh dependencies không có CVE hoặc ứng dụng đã qua security review.

Đề xuất: thêm dependency/secret checks phù hợp npm/Gradle, lưu kết quả và failure
policy rõ ràng; review thực tế các đường auth/CSRF/CORS/stock/payment. Audit này
không chạy CVE scan và không kết luận ứng dụng có hoặc không có lỗ hổng.

Đề xuất: thống nhất lựa chọn Node cho shell/verification/session launcher, giữ

Đề xuất: mở rộng conditional routing khi task thực sự cần; thêm eval bằng task

Đề xuất: ghi ngày/commit/môi trường cho snapshot, tách baseline nguồn bất biến
